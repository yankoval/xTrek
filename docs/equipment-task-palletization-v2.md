# Паллетизация в задании оборудования

Статус: проект целевого контракта  
Дата: 2026-07-31

Связанный файл: [JSON Schema](schemas/equipment-task-palletization.schema.json).

## Назначение

SSCC паллетов выделяются до начала работы оборудования. Это позволяет
проверить контрольное сканирование оператора по заранее известному значению и
исключить подтверждение случайно отсканированного чужого паллета.

Поля добавляются в существующее задание оборудования без удаления старых
полей:

```json
{
  "id": "T-EXAMPLE-20260731-0001",
  "reportSchemaVersion": 2,
  "numBoxesInPallet": 8,
  "plannedPalletCount": 2,
  "palletSsccReserve": 1,
  "palletNumbers": [
    "046070517921585754",
    "046070517921585761",
    "046070517921585778"
  ]
}
```

## Поля

| Поле | Тип | Обязательное для v2 | Описание |
|---|---|---:|---|
| `reportSchemaVersion` | integer | да | Требуемая версия отчёта оборудования. Для нового процесса равно `2`. |
| `numBoxesInPallet` | integer | да | Положительный норматив максимального количества закрытых коробов в одном паллете. |
| `plannedPalletCount` | integer | да | Расчётное число паллетов без страхового запаса. |
| `palletSsccReserve` | integer | да | Число дополнительно выделенных страховых SSCC. |
| `palletNumbers` | array[string] | да | Упорядоченный непустой список плановых и страховых SSCC паллетов, каждый по 18 цифр без AI `00`. |

Дополнительные поля существующего задания сохраняются без изменений.

## Правила формирования

1. `Quantity` производственного задания трактуется как плановое количество
   коробов.
2. Если в производственном задании указан `numBoxesInPallet`, значение должно
   быть положительным целым числом.
3. Плановое число паллетов равно
   `ceil(Quantity / numBoxesInPallet)`.
4. К плановому числу прибавляется страховой запас
   `pallet_sscc_reserve` из конфигурации xTrek. По умолчанию запас равен `1`.
5. Итоговое число элементов `palletNumbers` равно
   `plannedPalletCount + palletSsccReserve`.
6. Все SSCC запрашиваются одним вызовом до публикации задания и сохраняются в
   `palletNumbers`.
7. Повторный запуск для уже существующего задания не запрашивает другие SSCC.
8. SSCC, назначенный заданию, нельзя назначить другому заданию.
9. Если `numBoxesInPallet` отсутствует, создаётся совместимое задание
   `reportSchemaVersion: 1`, выделяется ровно один SSCC,
   `plannedPalletCount` равен `1`, а `palletSsccReserve` равен `0`.
10. Если `numBoxesInPallet` передан, но равен нулю, отрицателен или имеет
    неверный формат, формирование задания останавливается с ошибкой.

Источник значения `numBoxesInPallet` в производственном процессе пока должен
быть явно определён вызывающей процедурой.

Для выделения кодов используются параметры конфигурации xTrek:

| Параметр | Обязательный | Описание |
|---|---:|---|
| `sscc_service_url` | да | URL сервиса выделения SSCC. Для совместимости также читается старое имя `sscc_url`. |
| `sscc_prefix` | да | Префикс GS1, передаваемый сервису. |
| `sscc_extension` | нет | Дополнительный параметр сервиса SSCC. |
| `pallet_sscc_reserve` | нет | Страховой запас для v2, целое число не меньше нуля. По умолчанию `1`. |

Если сервис вернул меньше кодов, дублирующиеся коды или некорректный SSCC,
задание оборудования не публикуется.

## Правила использования оборудованием

Оборудование берёт SSCC из `palletNumbers` по порядку. Оно не генерирует и не
запрашивает паллетный SSCC самостоятельно. При открытии следующего паллета
используется следующее значение списка.

Финальный отчёт v2 может содержать несколько паллетов, но каждый его
`readyPallet[].palletNumber` должен входить в `palletNumbers`. Неиспользованные
назначенные SSCC в отчёт не включаются.

## Контрольное сканирование

После загрузки отчёта Yandex Serverless Function отправляет в MAX отдельное
изображение SSCC каждого паллета вместе со сводкой отчёта. Сканирование
считается успешным только если:

1. SSCC назначен этому заданию;
2. SSCC присутствует в загруженном отчёте;
3. этот паллет ещё не подтверждён либо повторно подтверждается тем же кодом.

Состояние подтверждения хранится отдельно от неизменяемого отчёта v2.
Обработка xTrek разрешается только после подтверждения всех паллетов,
перечисленных в отчёте.

## Обратная совместимость

Новые поля являются добавочными и не мешают старому приложению читать
задание. При отсутствии `numBoxesInPallet` задание автоматически получает
`reportSchemaVersion: 1` и ровно один элемент `palletNumbers`. После появления
норматива задание получает `reportSchemaVersion: 2`, расчётное число паллетов
и страховой запас.

Переключение выполняется по версии задания, а не по догадке на основании
содержимого пришедшего отчёта.
