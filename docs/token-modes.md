# Режимы работы с токенами

`TokenProcessor` работает в одном из двух режимов.

## Клиентский режим

`tokens_read_only=true` включён по умолчанию. `tokens_path` обязан указывать на
объект S3. Первый `TokenProcessor` в процессе скачивает `tokens.json`, проверяет
его и хранит снимок только в памяти. Остальные экземпляры в том же процессе
используют этот снимок без дополнительных запросов S3. Новый запуск CLI создаёт
новый процесс и обязательно получает новый снимок.

В этом режиме локальный `tokens.json` не читается и не используется при ошибке
S3. Методы публикации и `save_token()` запрещены. Клиентский код также не должен
вызывать `get_new_token()`.

## Серверный режим

Единственный контур выпуска токенов должен создавать процессор явно:

```python
TokenProcessor(tokens_read_only=False)
```

Перед изменением сервер обязательно читает актуальный объект S3. После выпуска
токена он сохраняет полный совместимый `tokens.json` и публикует его в S3.
Рекомендуемый запас обновления задаётся параметром
`tokens_refresh_before_expiry_seconds` (по умолчанию в примере — 900 секунд).

## Время

JWT `exp` трактуется как UTC и является авторитетным сроком JWT. Значения
`ДействуетС` и `ДействуетДо` с `Z` или offset используют указанную временную
зону. Исторические значения без зоны трактуются как `Europe/Moscow`. Формат
`tokens.json` при этом не меняется.

Штатные операции TokenProcessor журналируются на уровне `DEBUG`. На `INFO`
остаются только значимые события выпуска/публикации и принудительного обновления
после отказа авторизации; значения токенов не журналируются.
