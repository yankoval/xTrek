## Ошибки общего теста и их устранение

1. Первая попытка остановилась до выдачи UUID: сценарий неверно ожидал одиночную
   карточку, тогда как S3 хранит словари карточек по идентификаторам. VPS и Mac были
   возвращены в исходное состояние. Исправленный разбор отдельно проверен на трёх
   реальных организациях, после чего тест повторён. Поле `rollback_auth_verified`
   первой попытки не доказывает шесть API-проверок: список записей ещё не был собран.
   Токены в той попытке не выдавались и реестр не публиковался.
2. После второго запуска независимая проверка обнаружила приоритет старого
   `release.conf` над `99-uuid-cutover.conf` Celery. Override переименован в `zz-...`;
   проверены эффективные настройки и окружение живого процесса, а не только его статус active.
3. Старый `KillMode=control-group` прервал две задачи на ожидании подписи. По полным
   журналам нет перехода к обнаружению подписи и отправке в СУЗ, а квитанции отсутствовали.
   Перед восстановлением наличие квитанций проверено повторно. В очередь возвращены
   ровно два прежних события с исходными task ID; новые тестовые бизнес-задания не создавались.

нужно актуальные SUZ, а недействительные JWT выпустить и проверить отдельно. UUID
True API в legacy не записывать. Нельзя просто восстановить старый JSON и объявить откат успешным.

вернуть его исходную ветку, выполнить daemon-reload. Проверить эффективные каталоги
сервисов и авторизацию, затем запустить один legacy-мастер, Celery и таймер.
При сомнении в результате отправки бизнес-документа сначала сверять состояние СУЗ;
не возобновлять такие операции вслепую.
