# Состав наборов в КИН-отчёте

`xtrek.kinGenerator` использует рецепт `Hierarchy`: один `Kigu` с GTIN набора и список `Kit.Packs`, в котором каждая строка обозначает одну единицу вложения. Для состава 4+3 нужны четыре строки первого GTIN и три второго. `Kigu.CountPacksInside`, если указан, должен равняться семи. Генератор не получает состав из НК самостоятельно: рецепт необходимо предварительно сверить с карточкой товара.

Для каждого GTIN используется общий пул уникальных кодов из всех загруженных файлов. Повторные идентификаторы (в том числе с разными криптохвостами), некорректные коды и несовпадение количества строк рецепта блокируют генерацию. Каждый код расходуется только один раз.

Явно запрошенное `num_kits` требует полного количества вложений; при нехватке возвращается `None` с деталями в логах, количество не уменьшается. `strict_quantity=True` при отсутствии `num_kits` требует комплектацию для всех загруженных кодов SET. По умолчанию для прежних программных вызовов без количества сохраняется генерация максимально возможного числа полных наборов.

Пример: 3001 SET, 12000 кодов A, 9000 кодов B; `num_kits=3000, strict_quantity=True` создаёт 3000 наборов 4+3 и оставляет один SET. При 3001 коде каждого компонента запрос 3000 наборов завершается ошибкой, а не создаёт неполный отчёт.

Telegram-бот должен импортировать `xtrek` из зафиксированной зависимости; старый вложенный каталог `xTrek` не является установленным пакетом. Из локальной версии PythonAnywhere сохранены поддержка BOM и поля `codes` в конвертере XLSX.
