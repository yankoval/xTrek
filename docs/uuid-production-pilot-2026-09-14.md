## Изоляция и код

Запуск выполнен на `yc-worker` из нового каталога
`/tmp/xtrek-uuid-pilot-20260914-a9d76f`. Рабочий релиз не заменялся.
Использовалось установленное Python 3.9-окружение VPS, без установки пакетов на VPS.

Скопирована только карточка согласованной организации. Для сохранения исходных
контрольных записей JWT/СУЗ применена явная legacy-конвертация с московской зоной.
Рабочая папка организаций в S3 не синхронизировалась на запись.
Новый реестр имел отдельный ключ
`token-pilots/xtrek-uuid-pilot-20260914-a9d76f/registry-v2.json`
и собственную блокировку внутри того же префикса.

Работал настоящий отдельный Celery worker с пулом `solo`, concurrency=1, файловым
брокером Kombu и файловым backend в каталоге пилота. Это не eager-исполнение.
Две задачи проверяли баланс True API и выбирали независимую запись СУЗ.
Использованы реальные обработчики `task_prerun/task_postrun` из `xtrek.tasks`.
Тестовый процесс не подключался к рабочей YMQ-очереди и не получал её сообщения.
Пилот не проверяет боевой SQS-транспорт или prefork; эти настройки при рабочем
переключении требуют своего контроля.

Для ограничения выдачи добавлен параметр `tokens_purposes` со значением
`["true_api"]`. Без него сохраняется прежнее поведение обоих назначений.
Дополнительная проверка в пилотном сценарии запрещала любой вызов генератора
для другого назначения/ИНН. Перевыпуск СУЗ не выполнялся.
Перед запуском пройдены **179 локальных тестов и 14 вложенных проверок**, включая
обновление только True API при пороге, который иначе затронул бы СУЗ.

Подписи создавал существующий SignJS: attached для challenge, detached для пути
подписанного ping. Серверы CRPT приняли подписи. Новых бизнес-документов,
эмиссии, ввода, агрегации или производственных заданий не создавалось.
