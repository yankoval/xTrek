# Содержание этилового спирта в отчёте о нанесении

Для новых отчётов `chemistry` xTrek берёт фактическое содержание спирта из
`PasportData.alcoholVolume`. Если поле отсутствует или равно `null`, применяется
значение из настроек товарной группы. Существующие задания на нанесение
не дополняются и не перезаписываются.

## Настройки и входные данные

В действующий `suz_worker_config.json` нужно добавить раздел:

```json
{
  "product_group_settings": {
    "chemistry": {
      "alcoholVolume": "0"
    }
  }
}
```

Фрагмент также сохранён в
[`examples/product-group-settings.example.json`](examples/product-group-settings.example.json).
Он дополняет рабочую конфигурацию, а не заменяет её целиком. По текущему контракту
`config_loader` верхнеуровневые ключи заменяются целиком при объединении источников:
если раздел задан в нескольких файлах, источник с большим приоритетом должен
содержать все нужные настройки товарных групп.

Необязательное поле конкретного производственного задания имеет приоритет:

```json
{
  "PasportData": {
    "alcoholVolume": "4.5"
  }
}
```

Это фрагмент паспорта; остальные поля остаются прежними. Историческое имя
`PasportData` сохраняется. В модели поле имеет тип `Optional[str]` и значение
`None` по умолчанию. Значение по умолчанию для СУЗ задаётся именно в настройках,
а не в модели или константе Python. При отсутствии обоих источников создание
нового отчёта завершается ошибкой с указанием недостающей настройки.

В СУЗ передаётся строка `attributes.alcoholVolume`. Ноль из паспорта, включая
числовой `0`, не заменяется значением из настроек. Пустая строка, запятая вместо
точки, отрицательное число, 100, более одного десятичного знака и логическое
значение отклоняются без округления или подмены нулём. Корректное ненулевое
значение сохраняется. `null` трактуется как отсутствие значения.

## Основание и границы изменения

API СУЗ 3.0.40, редакция 67 от 24.09.2026, раздел 4.4.11.1.19, таблица 150,
страницы 312–314: объёмная доля этилового спирта передаётся строкой формата
`^([0-9]{1,2}|[0-9]{1,2}\.[0-9]{1})$`. Для отсутствующего спирта указывается `0`.
В примере PDF есть лишний пробел в имени `alcoholVolume `; правильный ключ по
таблице и примечаниям — `alcoholVolume`.

Примечание требует поле для единиц товара; для наборов и групповых упаковок
допускается отсутствие. В обычных новых отчётах `chemistry` применяется единое
правило паспорта и настроек. Для `SPLITMARK` все три атрибута — дата производства,
срок годности, содержание спирта — запрещены. Помощник формирования атрибутов
учитывает исключение; поддержка самой операции `SPLITMARK` этим изменением
не добавляется. Другие товарные группы поле автоматически не получают.

Оба генератора используют одинаковое правило:

- `create_utilisation_task_from_report` — отчёт по данным оборудования;
- `create_utilisation_task` — отчёт по полученным кодам, в том числе через
  `create_virtual_utilisation_task` для виртуальных компонентов наборов.

Паспорт читается и при передаче обеих дат аргументами: явно заданные даты не
отменяют приоритет `PasportData.alcoholVolume`. Для виртуального компонента
используется его собственный паспорт. Генерация паспорта компонента по составу
набора не копирует содержание спирта всего набора на отдельный GTIN; если
собственного значения нет, применяется настройка группы.

Существующие `utilisationTasks/<id>.json` возвращаются генераторами без
перезаписи, независимо от наличия поля. Их статусы/теги при генерации не меняются.
Отправитель не добавляет атрибут перед подписью. Нет миграции, массового
пересоздания или повторной отправки старых отчётов. Новое задание на нанесение
может использовать существующий производственный заказ как источник паспорта.

## План и приёмка

1. Добавить необязательное поле в `PasportData`; десериализаторы оставляют
   `None`, вместо заполнения необязательных полей пустой строкой.
2. Ввести раздел `product_group_settings` в настройках и общий выбор/проверку
   `alcoholVolume` для новых отчётов. Пример значения `chemistry` — `"0"`.
3. Подключить оба генератора. Существующие задания сохранять; отправку и подпись
   не использовать для исправления старых документов.
4. Проверить приоритет паспорта, отсутствие/null, числовой и строковый ноль,
   изменённое значение по умолчанию, формат, UNIT/виртуальные компоненты,
   неизменность старых заданий и соответствие подписанных и отправленных байтов.
5. Выполнить реальную подачу нового отчёта в согласованном тестовом контуре.
   Проверить конечное тело, подпись, `reportId` и асинхронный `SUCCESS`.
   Один HTTP 200 не означает завершённую проверку. Сохранить идентификаторы,
   статус, время, окружение и контрольную сумму тела без токенов и полных кодов.
6. После проверки создать коммит и PR. Производственный выпуск выполнять
   отдельно: сначала настроить `product_group_settings`, затем обновить код.
   Существующие задания не пересоздавать.

Проверка контура обязательна: прежний `suz_worker_config_test.json` меняет
хранилище на `cloud-ediagg-test`, но сам по себе не переводит СУЗ, токены и подпись
в sandbox. Такой запуск является обращением в production и требует отдельного
согласования. Настройки и конечный адрес СУЗ фиксируются в результате теста.

Рекомендуемый срок выпуска — до объявленного ориентировочного включения проверки
в конце октября 2026 года; точная дата в исходном письме не указана.

## Проверки этой ветки

Реализация пунктов 1–4 готова. Целевые проверки: 175 тестов пройдено, включая
новую проверку атрибута, виртуальное нанесение/ввод, UNIT/SET, транспорт СУЗ
и подпись. Команда:

```bash
python -m pytest -q tests/test_utilisation_alcohol_volume.py \
  tests/test_virtual_utilisation.py tests/test_virtual_introduce.py \
  tests/test_create_virtual_tasks.py tests/test_tasks_unit_set_flow.py \
  tests/test_suz_new_methods.py tests/test_sign.py
```

Полный набор CI (`python -m pytest -q tests/`): **714 passed, 9 skipped,
14 subtests passed**. Изменённые модули проверены на синтаксическую совместимость
с Python 3.9; `git diff --check` проходит.

Реальная подача выполнена 07.10.2026 по отдельному согласованию: производственная
СУЗ, тестовое хранилище S3 и серверная подпись Фитокосметик. Выпущен один новый
код, старые коды не использовались. [Результат проверки](chemistry-alcohol-volume-live-test.md).
