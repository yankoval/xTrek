# Компактные сообщения MAX

Принято 19.10.2026 после проверки пользователем примера в чате `test`.
В мобильном приложении пользователя числовая строка переносится после 21 цифры.
Веб-эмуляция давала 26–35 цифр на телефонных ширинах и не заменяет проверку
нативного приложения. Это наблюдение, а не ограничение MAX API.

## Общая рекомендация

- Целевая длина видимой строки — **до 20 символов**, включая пробелы и подписи.
  Размер шрифта и ширина букв могут вызвать перенос и раньше.
- Одна сущность/показатель на строку; между карточками — пустая строка.
- Не использовать широкие таблицы, выравнивание пробелами и склеенные показатели.
- Длинную подпись и значение разделять переносом; имена переносить по словам.
- Не обрезать и не менять идентификаторы, SSCC, GTIN, даты, количество и суммы.
  Неделимый идентификатор длиннее 20 символов — допустимое исключение:
  оставить целиком на отдельной строке для копирования.
- Диапазон дат показывать двумя строками с «С» и «По», сохраняя год и время.
- Использовать настоящие `\n`, а не `<br>` или CSS; HTML-разметка не входит
  в подсчёт видимой длины. Число сообщений без необходимости не увеличивать.
- Сохранять все группировки, подытоги и общий итог, не пересчитывать их ради вёрстки.

## Отчёты

HTML `--profile messenger` для `tasks`, `tasks-grouped`, `equipment-grouped`
использует вертикальные карточки с короткими подписями («Ярлыков» вместо
«Паспортов (ярлыков)»). Общая модель данных, фильтры и расчёты не меняются.
PDF, browser/printer HTML и файловый Markdown остаются без изменений.
Бот получает окончательный вариант из xTrek и не переписывает его через LLM.

```text
Оператор:
Иванов И.И.

Артикул:
1124-77-001
Заданий: 16
Ярлыков: 2 285
Кодов: 13 710
```

## Ярлыки паллет и другие уведомления

Ту же рекомендацию применять при последующих изменениях подписей к изображениям:
паллету, SSCC, количество коробов и штук выводить отдельными строками; длинный
ID отчёта — отдельной строкой целиком; диапазоны коробов переносить между
элементами, сохраняя ведущие нули. Для длинного перечня цель 20 символов не
оправдывает потерю данных или рассылку дополнительных сообщений.
Изображение/PDF самого ярлыка имеет отдельные правила печатной вёрстки.
Эта рекомендация не меняет исторические сообщения, подтверждения доставки,
идентификаторы и механизм защиты от повторных отправок.
