# Безопасные имена productionOrder

При создании обычного `T-…` и виртуального `V-…` заказа каждый компонент
производного имени проходит через `safe_production_order_component`.

Сохраняются Unicode-буквы, цифры, комбинируемые знаки и символы `.`, `_`, `-`.
Каждый другой символ заменяется на `_`, включая `/`, `\`, пробелы,
управляющие символы и пунктуацию, проблемную для файлов и URL:
`<`, `>`, `:`, `"`, `|`, `?`, `*`, `%`, `#`, `&`, `+`.
Точки в конце компонента удаляются; пустой результат заменяется на `unknown`.
Расширение итогового файла всегда `.json`.

Например, `Batch_number=07/2029-C-01-20` даёт компонент имени
`07_2029-C-01-20`. Кириллица, включая исторические обозначения партий,
сохраняется без преобразования в латиницу.

Сам S3 допускает многие из этих символов. Фильтр обеспечивает совместимость
плоского идентификатора с дальнейшей обработкой ключей, URL и локальных файлов.
Исходные `Article`, `Batch_number` и остальные поля документа не изменяются.
UUID входного файла сохраняется, если он записан в обычном формате.

Возвращаемый ID обычного заказа совпадает с полным именем опубликованного
файла без `.json`. Он больше не вычисляется через `Path(...).stem`, который
отбрасывал часть имени перед `/`. Временный файл получает отдельное случайное
имя и не использует небезопасное имя входного объекта.

Изменение применяется к новым созданиям заказов. Уже опубликованные объекты,
результаты завершённых операций и сохранённые ошибочные ID не мигрируются.
Для их восстановления нужен отдельный план с учётом состояния операций.
